# Cara Update Changelog Saat Rilis Versi Baru

Panduan untuk memastikan changelog di production ikut terupdate saat melakukan update file.

## 🎯 Masalah

Saat melakukan update file via updater, changelog di database production tidak ikut terupdate karena:
1. File `app/Database/changelogs_sync.php` tidak diupdate
2. Changelog hanya ada di database development

## ✅ Solusi

Ada 2 cara untuk memastikan changelog terupdate:

---

## Cara 1: Update Manual File changelogs_sync.php (Recommended)

### Langkah-langkah:

#### 1. Export Changelog dari Database Development

Jalankan query ini di database development (localhost):

```sql
SELECT * FROM changelogs ORDER BY release_date DESC;
```

#### 2. Update File changelogs_sync.php

Edit file: `app/Database/changelogs_sync.php`

Format:
```php
<?php

// This file is automatically generated for synchronization between development and production.
// Created: <?= date('Y-m-d H:i:s') ?>

return array (
  0 => 
  array (
    'id' => '6',  // ID baru
    'version' => '1.2.0',  // Versi baru
    'release_date' => '2026-02-21',
    'description' => 'Perbaikan bug hosting:
- Tambah tabel ci_sessions untuk session handler
- Perbaiki error shell_exec() di sistem lisensi
- Update migrasi database
',
    'is_stable' => '1',
    'created_at' => '2026-02-21 10:00:00',
    'updated_at' => '2026-02-21 10:00:00',
  ),
  // ... changelog lama di bawah
);
```

#### 3. Generate Patch ZIP

1. Buka halaman Updater di localhost
2. Klik "Download Zip" untuk generate patch
3. File `changelogs_sync.php` yang sudah diupdate akan include di ZIP

#### 4. Upload & Update di Production

1. Upload ZIP ke production
2. Jalankan "Update File" di halaman Updater
3. Jalankan "Jalankan Migrasi" - ini akan otomatis sync changelog!

---

## Cara 2: Menggunakan Helper Script (Otomatis)

### Buat Script Helper

Buat file: `app/Database/sync_changelogs.php`

```php
<?php

/**
 * Script untuk generate changelogs_sync.php dari database
 * Jalankan di localhost sebelum generate patch
 */

require __DIR__ . '/../../vendor/autoload.php';

// Bootstrap CodeIgniter
$app = require_once FCPATH . '../app/Config/Paths.php';
$app = new \CodeIgniter\CodeIgniter($app);
$app->initialize();

// Get database connection
$db = \Config\Database::connect();

// Get all changelogs
$changelogs = $db->table('changelogs')
    ->orderBy('release_date', 'DESC')
    ->get()
    ->getResultArray();

// Generate PHP array
$output = "<?php\n\n";
$output .= "// This file is automatically generated for synchronization between development and production.\n";
$output .= "// Created: " . date('Y-m-d H:i:s') . "\n\n";
$output .= "return " . var_export($changelogs, true) . ";\n";

// Write to file
$syncFile = __DIR__ . '/changelogs_sync.php';
file_put_contents($syncFile, $output);

echo "✅ Changelog sync file updated successfully!\n";
echo "📁 File: {$syncFile}\n";
echo "📊 Total changelogs: " . count($changelogs) . "\n";
```

### Cara Menggunakan:

```bash
# Di localhost, sebelum generate patch
cd app/Database
php sync_changelogs.php
```

Atau tambahkan ke Updater controller agar otomatis:

```php
// Di method generatePatch(), sebelum create ZIP
$this->syncChangelogsToFile();
```

## Cara 3: Tambah Changelog Langsung di Production (Emergency)

Jika lupa update file sync, bisa tambah manual di production:

### Via phpMyAdmin:

```sql
INSERT INTO changelogs (version, release_date, description, is_stable, created_at, updated_at)
VALUES (
    '1.2.0',
    '2026-02-21',
    'Perbaikan bug hosting:
- Tambah tabel ci_sessions
- Perbaiki error shell_exec()
',
    1,
    NOW(),
    NOW()
);
```

### Via Updater (Tambah Fitur):

Tambahkan form di halaman Updater untuk input changelog manual.

## 🔄 Workflow Update yang Benar

### Development (Localhost):

1. ✅ Buat fitur baru
2. ✅ Update database (migrasi)
3. ✅ Tambah changelog di database development
4. ✅ **Update file `changelogs_sync.php`** (PENTING!)
5. ✅ Update `LAST_UPDATE` di Constants.php (otomatis saat generate patch)
6. ✅ Generate patch ZIP
7. ✅ Test di localhost

1. ✅ Backup database
2. ✅ Upload patch ZIP
3. ✅ Jalankan "Update File"
4. ✅ Jalankan "Jalankan Migrasi" (otomatis sync changelog!)
5. ✅ Test aplikasi

## 🐛 Troubleshooting

### Changelog Tidak Muncul di Production

**Cek:**
1. Apakah file `changelogs_sync.php` sudah diupdate?
2. Apakah sudah jalankan "Jalankan Migrasi" setelah update file?
3. Apakah ada error di log?

**Solusi:**
```bash
# Cek file sync
cat app/Database/changelogs_sync.php

# Cek database
SELECT * FROM changelogs ORDER BY release_date DESC LIMIT 5;

# Jalankan sync manual via controller
# Atau tambah changelog manual via SQL
```

### File changelogs_sync.php Tidak Ter-include di ZIP

**Solusi:**
Pastikan folder `app/Database` ter-include saat generate patch.

Di `Updater::generatePatch()`:
```php
$folders = ['app', 'public', 'modules'];
```

Folder `app` sudah include, jadi `app/Database/changelogs_sync.php` seharusnya ter-include.

### Changelog Lama Hilang

**Penyebab:**
Method `syncChangelogsFromData()` menggunakan `emptyTable()` yang menghapus semua data lama.

**Solusi:**
Pastikan file `changelogs_sync.php` berisi SEMUA changelog (lama + baru), bukan hanya yang baru.

## ✨ Best Practices

1. **Selalu update `changelogs_sync.php`** sebelum generate patch
2. **Gunakan version numbering yang konsisten** (semantic versioning)
3. **Tulis deskripsi yang jelas** dan informatif
4. **Test di localhost** sebelum deploy
5. **Backup database** sebelum update production
6. **Dokumentasikan** setiap perubahan
