## Hash Verification

### How It Works

1. **SecurityGuard** library checks file integrity on application load
2. Compares current file hash with stored hash in `.security_hash`
3. If mismatch detected, triggers tampering alert
4. Prevents application from running if critical files are modified

## Important Notes

### Protected vs Non-Protected Files

**Protected files (7):** License and security core files that are critical for application integrity.

**Non-protected files:** Other application files including controllers, models, views, helpers, and filters that are not in the protected list.

**Why only 7 files?** The hash protection is specifically for license and core security files to prevent tampering with the licensing system and core security mechanisms.

### Two Types of Hash

1. **`.lic_hash`** (SHA-1)
   - For license files only
   - Generated by `generate_license_hash.php`
   - Files: LicenseGuard, LicenseFilter, LicenseModel

2. **`.security_hash`** (SHA-256)
   - For critical security files
   - Generated by `generate_security_hash.php`
   - Files: 7 core files listed above

### Security Considerations

- ✅ Hash files are in `.gitignore` (not committed to repo)
- ✅ Must be regenerated after modifying protected files
- ✅ Only accessible from localhost
- ✅ Uses strong hash algorithm (SHA-256)
- ✅ Prevents unauthorized modifications to core files

## Troubleshooting

### Tampering Alert After Update

**Problem:** Application shows tampering alert for `Config/Filters.php`

**Solution:**
```bash
# Regenerate security hash
php generate_security_hash.php

# Verify hash file exists
ls -la app/Config/.security_hash

# Check file permissions
chmod 644 app/Config/.security_hash
```

### Hash Generation Failed

**Problem:** Cannot write `.security_hash` file

**Solution:**
```bash
# Check directory permissions
chmod 755 app/Config/

# Check if file exists and is writable
chmod 644 app/Config/.security_hash

# Run script again
php generate_security_hash.php
```
