PERTANYAAN:
"Dalam instalasi CI4 ada dua kemungkinan: aplikasi dijalankan di /public 
(seharusnya) atau langsung di root. Apakah sistem lisensi terpengaruh?"

JAWABAN:
✅ TIDAK TERPENGARUH! Sistem lisensi sudah menggunakan CI4 constants yang 
   otomatis menyesuaikan dengan struktur instalasi apapun.

═══════════════════════════════════════════════════════════════════════════════

📁 DUA STRUKTUR INSTALASI CI4:

STRUKTUR 1: Standard (Recommended)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
/var/www/html/aplikasi/
├── app/
│   ├── Config/
│   │   ├── .lic_hash          ← Hash files
│   │   └── .security_hash
│   └── ...
├── public/                     ← DOCUMENT ROOT (Apache/Nginx point here)
│   ├── index.php              ← Entry point
│   └── ...
├── writable/
│   ├── .install_id            ← Installation ID
│   └── .production_mode
└── ...

URL: http://domain.com/ → /var/www/html/aplikasi/public/index.php

STRUKTUR 2: Root Installation
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
/var/www/html/aplikasi/
├── app/
│   ├── Config/
│   │   ├── .lic_hash          ← Hash files (SAMA!)
│   │   └── .security_hash
│   └── ...
├── index.php                   ← Entry point (moved from public/)
├── .htaccess
├── writable/
│   ├── .install_id            ← Installation ID (SAMA!)
│   └── .production_mode
└── ...

URL: http://domain.com/ → /var/www/html/aplikasi/index.php

═══════════════════════════════════════════════════════════════════════════════

🔍 MENGAPA TIDAK TERPENGARUH?

1. MENGGUNAKAN CI4 PATH CONSTANTS
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   
   APPPATH    = '/var/www/html/aplikasi/app/'
   WRITEPATH  = '/var/www/html/aplikasi/writable/'
   
   ✅ Constants ini SAMA untuk kedua struktur!
   ✅ Otomatis menyesuaikan dengan instalasi

2. PATH YANG DIGUNAKAN SISTEM LISENSI
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   
   File Hash:
   $hashFile = APPPATH . 'Config/.lic_hash';
   
   Struktur 1: /var/www/html/aplikasi/app/Config/.lic_hash
   Struktur 2: /var/www/html/aplikasi/app/Config/.lic_hash
   ✅ SAMA! Tidak terpengaruh
   
   Install ID:
   $installFile = WRITEPATH . '.install_id';
   
   Struktur 1: /var/www/html/aplikasi/writable/.install_id
   Struktur 2: /var/www/html/aplikasi/writable/.install_id
   ✅ SAMA! Tidak terpengaruh

3. YANG BERBEDA (TAPI JUSTRU BAGUS!)
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   
   $_SERVER['DOCUMENT_ROOT']
   
   Struktur 1: /var/www/html/aplikasi/public
   Struktur 2: /var/www/html/aplikasi
   ❌ BERBEDA
   
   Tapi ini digunakan hanya untuk generate machine_id!
   ✅ Justru BAGUS karena:
      • Setiap instalasi tetap unik
      • Mencegah abuse (1 lisensi untuk 2 instalasi)
      • Machine ID berbeda untuk struktur berbeda

═══════════════════════════════════════════════════════════════════════════════

📊 PERBANDINGAN PATH CONSTANTS:

┌─────────────────────┬──────────────────────┬──────────────────────┬────────┐
│ Constant            │ Struktur 1 (/public) │ Struktur 2 (root)    │ Sama?  │
├─────────────────────┼──────────────────────┼──────────────────────┼────────┤
│ APPPATH             │ .../app/             │ .../app/             │ ✅ YA  │
│ WRITEPATH           │ .../writable/        │ .../writable/        │ ✅ YA  │
│ ROOTPATH            │ .../aplikasi/        │ .../aplikasi/        │ ✅ YA  │
│ FCPATH              │ .../public/          │ .../aplikasi/        │ ❌ BEDA│
│ DOCUMENT_ROOT       │ .../public           │ .../aplikasi         │ ❌ BEDA│
└─────────────────────┴──────────────────────┴──────────────────────┴────────┘

Yang Digunakan Sistem Lisensi:
✅ APPPATH    - Untuk file hash dan library
✅ WRITEPATH  - Untuk install_id dan production_mode
⚠️  DOCUMENT_ROOT - Hanya sebagai komponen machine_id (justru bagus!)

═══════════════════════════════════════════════════════════════════════════════

✅ KESIMPULAN:

1. SISTEM LISENSI TIDAK TERPENGARUH
   • Menggunakan APPPATH dan WRITEPATH yang selalu konsisten
   • Tidak bergantung pada FCPATH atau document root untuk file kritis
   • DOCUMENT_ROOT hanya untuk machine_id (justru bagus)

2. KEDUA STRUKTUR FULLY SUPPORTED
   • Struktur 1 (Standard /public): ✅ Supported
   • Struktur 2 (Root Installation): ✅ Supported
   • Auto-generate hash: ✅ Berfungsi di kedua struktur
   • Machine binding: ✅ Berfungsi di kedua struktur

3. MACHINE ID TETAP UNIK
   • Perbedaan document root membuat machine_id berbeda
   • Mencegah abuse lisensi
   • Setiap instalasi tetap unik

❓ FAQ:

Q: Apakah perlu update code untuk support root installation?
A: ❌ Tidak perlu! Sudah otomatis support.

Q: Apakah machine_id berbeda untuk kedua struktur?
A: ✅ Ya, dan ini BAGUS untuk mencegah abuse.

Q: Apakah hash files tetap di lokasi yang sama?
A: ✅ Ya, selalu di app/Config/ untuk kedua struktur.

Q: Apakah perlu regenerate hash saat pindah struktur?
A: ✅ Ya, otomatis regenerate karena machine_id berubah.

Q: Apakah lisensi perlu diaktivasi ulang saat pindah struktur?
A: ✅ Ya, karena dianggap instalasi baru (machine_id berbeda).
